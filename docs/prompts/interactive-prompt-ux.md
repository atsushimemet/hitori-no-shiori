現在の Next.js プロジェクトをベースに、ユーザーがタイプライターの入力例を理解したあと、自分でテキストボックスにカーソルを合わせたくなる体験を実装してください。

目的

ファーストビューでは、10個のプロンプト例がテキストボックス内にタイプライター表示されています。

この実装の目的は、ユーザーが
「こういう曖昧な気分を入れていいんだ」
と理解したあと、自然に自分の言葉を入力し始められる状態を作ることです。

単に入力欄をfocusできるようにするのではなく、
“見ている状態”から“自分で相談する状態”へ移る体験を丁寧に作ってください。

体験方針

ユーザーがテキストボックスにカーソルを合わせた瞬間、サイトは以下のように振る舞ってください。

1. タイプライター表示を静かに止める
2. 表示中の入力例を薄くフェードアウトする
3. テキストボックスが少しだけ明るく、入力可能な状態になる
4. カーソルが自然に表示される
5. プレースホルダーとして短い一文を表示する
6. ユーザーが入力を始めたら、完全に通常の入力欄として振る舞う

この変化は、急に切り替えるのではなく、
「ここからはあなたの番です」と伝わるようにしてください。

表示文言

focus前、タイプライター中：

* 10個のプロンプト例を順番に表示する

focus後、まだ未入力の場合：

今日は、どんなひとり時間にしますか？

入力中：

* ユーザーの入力テキストを表示する

CTA：

ひとり時間をAIと探す

状態設計

以下の状態を明確に分けて実装してください。

idle

* タイプライターが動いている
* 入力例を表示している
* ユーザーはまだ操作していない

intent

* ユーザーがテキストボックスにhover、または近づいた
* 入力例の動きを少しだけ落ち着かせる
* テキストボックスをわずかに明るくする
* 「入力できる」気配を出す

focused

* ユーザーがfocusした
* タイプライターを停止する
* 入力例をフェードアウトする
* 実入力モードに切り替える

typing

* ユーザーが1文字以上入力している
* CTAを少しだけ強調する
* Enterキーでも送信できそうにする

submitted

* ユーザーがCTAを押した、またはEnterを押した
* 入力内容を保持する
* 仮の「栞を作っています」状態へ遷移する
* 実際のAI連携は不要

usePromptInteraction.ts

新しく作成してください。

役割：

* prompt boxの状態を管理する
* idle / intent / focused / typing / submitted を扱う
* hover、focus、blur、change、submitを管理する
* タイプライターを止めるべきかどうかを返す

返す値の例：

type PromptInteractionState = "idle" | "intent" | "focused" | "typing" | "submitted"
return {
  state,
  value,
  setValue,
  isTypewriterPaused,
  handleMouseEnter,
  handleMouseLeave,
  handleFocus,
  handleBlur,
  handleChange,
  handleSubmit,
}

useTypewriter.ts の更新

既存の useTypewriter.ts を更新してください。

以下を受け取れるようにしてください。

{
  prompts: string[]
  paused?: boolean
}

paused が true のとき：

* 新しい文字を追加しない
* 削除もしない
* 現在の表示文字を保持する
* focus切り替え側のフェードアウトに任せる

reduced motion の場合：

* タイプライターは動かさない
* 一定時間ごとに文章を静かにフェード切り替えする
* focus時には即座に停止する

Motionの使い方

Motion / Framer Motion を使って、以下の変化を実装してください。

テキストボックス

idle：

* 通常の明るさ
* 影はごく薄い
* borderは控えめ

intent：

* 少しだけ浮く
* borderがわずかに濃くなる
* 内側が少し明るくなる

focused：

* タイプライター文がフェードアウト
* 実入力用のカーソルが表示される
* borderがやさしく強調される

typing：

* CTAが少しだけ存在感を増す
* テキストボックスの高さは変えすぎない

submitted：

* テキストボックス全体が少しだけ上に移動
* 下に「栞を作っています」を表示する

推奨するMotion要素

* motion.form
* motion.div
* motion.textarea または motion.input
* motion.button
* AnimatePresence
* variants

Anime.jsの使い方

Anime.jsは、以下のような補助演出に限定してください。

* focus時に罫線が一度だけすっと整う
* submitted時に小さな栞の点がふわっと出る
* 「栞を作っています」の点が静かに呼吸する

Anime.jsを使わなくても自然に実装できる場合は、Motionだけでも構いません。
ただし、過剰な演出は避けてください。

UI仕様

テキストボックス

* Claude Desktop の入力欄のように、自然に会話が始まりそうな見た目
* 大きめの角丸
* 内側の余白を広く
* 1行入力でも、少し高さのあるボックスにする
* スマホでは画面幅に合わせて自然に広がる
* 長い文章は折り返す
* 実装は textarea 推奨

focus時の演出

focusしたら、タイプライター例を消して以下を表示してください。

今日は、どんなひとり時間にしますか？

ただし、これは入力値ではなくplaceholderとして扱ってください。

ユーザーが入力したら、placeholderは消してください。

blur時の挙動

ユーザーが何も入力せずにblurした場合：

* 少し待ってから idle に戻す
* タイプライター表示を再開する
* 急に戻らず、静かに戻す

ユーザーが入力済みの場合：

* 入力内容を保持する
* typing 状態を保つ
* タイプライターは再開しない

CTA仕様

CTA文言：

ひとり時間をAIと探す

状態によって見た目を変えてください。

* idle：通常
* intent：少しだけ明るい
* focused：押せることが分かる
* typing：最も自然に押したくなる状態
* submitted：disabledまたはloading表現

ユーザーが未入力のままCTAを押した場合：

* 現在表示中、または直近で表示されていたタイプライター例を入力値として扱ってよい
* そのまま「栞を作っています」状態へ進める

submitted状態

送信後、実際のAI連携は不要です。

代わりに、テキストボックスの下に以下を表示してください。

栞を作っています

その横または下に、小さな点が3つ、静かに呼吸するように動くローディングを表示してください。

派手なスピナーは禁止です。

アクセシビリティ

* textareaには適切な aria-label を付ける
* CTAはbuttonとして実装する
* Enterキーで送信できるようにする
* Shift + Enterでは改行できるようにする
* reduced motionに対応する
* focus ringを消さない。世界観に合う見た目に調整する
* キーボード操作だけでも使えるようにする

重要な禁止事項

* focus時に急に画面全体を動かさない
* 強いバウンドや派手な発光を入れない
* タイプライター文と実入力文が同時に見えて混乱する状態にしない
* 入力欄がクリックできるのか分からない見た目にしない
* 送信前に余計な説明文を増やさない
* 文字量を増やしすぎない

完了条件

* ユーザーが入力例を見たあと、自然にテキストボックスへカーソルを合わせたくなる
* hover / focus / typing / submit の状態遷移がある
* focus時にタイプライターが止まり、実入力モードに切り替わる
* 未入力でblurしたら自然にタイプライターへ戻る
* 入力済みなら内容を保持する
* CTA「ひとり時間をAIと探す」が状態に応じて自然に強調される
* Enterで送信、Shift+Enterで改行できる
* submitted時に「栞を作っています」が表示される
* TypeScript / lint エラーがない
