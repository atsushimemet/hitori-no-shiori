現在の Next.js プロジェクトをベースに、/casual-bar ページでカードをすべて閲覧したユーザーに対して、行ってみたいお店があったかをヒアリングし、時間を確認したうえでGoogle Calendar登録へつなげるフローを実装してください。

目的

/casual-bar ページは、バーの候補を表示するだけで終わらせません。

ユーザーがカードを見終わったあと、
「今日のひとり時間を実際の予定にする」
ところまで自然につなげたいです。

実装したい体験

ユーザーが /casual-bar ページのバー候補カードをすべて閲覧したあと、ページ下部またはカード一覧の後に、AIからの問いかけを表示してください。

1. 行ってみたいお店があったかを聞く

表示文言：

行ってみたいお店はありましたか？

選択肢：

あった
まだ迷っている

2. 「あった」を選んだ場合

行ってみたいお店を選べるようにしてください。

表示文言：

どのお店に行ってみたいですか？

選択肢は、現在表示している最大3件のバー名を使ってください。

例：

Bar Amber Note
Evening Stand Ebisu
Book & Glass Ebisu

3. 店舗選択後、何時に行くかを聞く

表示文言：

何時に行きますか？

入力形式は、まずはシンプルで構いません。

候補チップ：

今日 19:00
今日 20:00
明日 19:00

自由入力：

例：今日の20時

4. 時間入力後、Google Calendar登録へ進める

時間が選択または入力されたら、予定登録の確認を表示してください。

表示文言：

Google Calendarに予定を登録しますか？

確認内容：

お店：選択したバー名
時間：選択または入力した時間

CTA：

Google Calendarに登録する

サブCTA：

あとで決める

Google Calendar連携について

現時点では、実際のGoogle Calendar API連携は不要です。

ただし、将来的に連携しやすいように、登録処理は関数として分離してください。

例：

async function createCalendarEvent(params: {
  barName: string
  datetimeText: string
}) {
  // TODO: Google Calendar API integration
  return { ok: true }
}

現状では、CTA押下後にモックで成功状態を表示してください。

成功文言：

予定の栞をはさみました。

補足文言：

当日は、少し早めに出発できるようにしておきましょう。

「まだ迷っている」を選んだ場合

迷っているユーザーには、無理に予定登録を促さず、もう一度カードを見られる導線を表示してください。

表示文言：

もう少し眺めてから決めましょう。

CTA：

候補を見返す

押下すると、バー候補カード一覧の先頭へスクロールしてください。

表示タイミング

このヒアリングUIは、カード一覧をすべて閲覧したあとに表示してください。

実装方法はどちらでも構いません。

* 3枚目のカードが表示領域に入ったあとに表示
* ユーザーがページ下部までスクロールしたあとに表示
* カード一覧の最後に常時表示

ただし、理想は以下です。

1. 最初はヒアリングUIを強く出しすぎない
2. ユーザーがカードを見たあと、静かに表示される
3. 「押し売り」ではなく、「予定にしてみますか？」という温度感にする

Motion / Anime.js の利用

Motion または Anime.js を必ず使ってください。

推奨は Motion です。

ヒアリングUIの動き

* カード閲覧後に、下から少し浮かび上がる
* opacity: 0 → 1
* y: 16px → 0
* blur: 6px → 0px

選択肢の動き

* 選択したチップが、そっと強調される
* 次の質問が、前の質問の下に静かに現れる
* 質問が増えていくたびに、会話が続いている感じを出す

Google Calendar登録成功時

* 成功状態は派手なチェックアニメーションではなく、栞がそっと挟まるような表現にしてください
* 小さな栞マーク、または細い線が差し込まれるようなMotionを入れてください

例：

細い栞が上からすっと入る
↓
「予定の栞をはさみました。」が表示される

状態設計

以下のような状態を管理してください。

type BarFollowupStep =
  | "ask_interest"
  | "select_bar"
  | "ask_time"
  | "confirm_calendar"
  | "calendar_loading"
  | "calendar_success"
  | "undecided"

状態の流れ：

ask_interest
↓ あった
select_bar
↓ 店舗選択
ask_time
↓ 時間選択または入力
confirm_calendar
↓ Google Calendarに登録する
calendar_loading
↓ モック成功
calendar_success

「まだ迷っている」の場合：

ask_interest
↓ まだ迷っている
undecided

UIトーン

このフローは、予約やタスク管理のように硬くしないでください。

「予定登録」ではあるが、世界観としては
“今日の自分のために、時間へ栞をはさむ”
という印象にしてください。

避けたい表現：

予約しますか？
カレンダー登録を実行します
イベントを作成しました

使いたい表現：

予定の栞をはさみますか？
予定の栞をはさみました。

アクセシビリティ

* 選択肢はbuttonとして実装する
* Google Calendar登録CTAもbuttonとして実装する
* ローディング中はbuttonをdisabledにする
* 状態変化には aria-live="polite" を付ける
* キーボード操作だけでも進められるようにする
* reduced motionに対応する

禁止事項

* 実際のGoogle Calendar APIは呼ばない
* APIキーや認証処理を追加しない
* 登録を強く迫るUIにしない
* カード閲覧前から大きく予定登録を出しすぎない
* 派手なチェックマークや紙吹雪を使わない
* 入力欄や選択肢が多すぎて重くならないようにする
* 文字量を増やしすぎない

完了条件

* /casual-bar ページでカード閲覧後にヒアリングUIが表示される
* 「行ってみたいお店はありましたか？」が表示される
* 「あった」を選ぶと、店舗選択へ進む
* 店舗選択後、何時に行くかを聞く
* 時間選択または入力後、Google Calendar登録確認へ進む
* 「Google Calendarに登録する」を押すと、モックで成功する
* 成功文言「予定の栞をはさみました。」が表示される
* 「まだ迷っている」を選ぶと、候補を見返す導線が表示される
* Motion または Anime.js を使った、ひとりの栞らしい控えめで独自性のある動きがある
* TypeScript / lint エラーがない
